# 高性能后端开发计划

> 关联文档：`docs/backend-architecture.md`
> 状态：草案 v0.1

---

## 1. 目标

在 WindLiberity（动漫视频流媒体）场景下，落地一套高性能、高可用、可水平扩展的后端系统。

核心目标：

- 核心读接口 P99 < 100ms
- 系统可用性 99.95%
- 峰值读 QPS 10 万+，写 QPS 2 万+
- 视频分发由 CDN 承载，源站回源率 < 5%

---

## 2. 技术栈

- 语言：Go（核心服务）
- 网关：APISIX / Envoy
- 数据库：MySQL 8（分库分表 + 读写分离）
- 缓存：Redis Cluster + 本地缓存
- 消息队列：Kafka
- 搜索：Elasticsearch
- 存储：MinIO / S3 对象存储 + CDN
- 编排：Kubernetes + Helm + ArgoCD

---

## 3. 阶段划分

```mermaid
flowchart LR
    A[阶段一 MVP 单体] --> B[阶段二 服务拆分]
    B --> C[阶段三 高可用]
    C --> D[阶段四 规模化]
```

### 阶段一：MVP 单体（跑通业务）

- [ ] 搭建 Go 服务骨架，统一日志 / 错误码 / 配置
- [ ] 用户模块：注册、登录、JWT 鉴权
- [ ] 内容模块：番剧、剧集 CRUD 与详情接口
- [ ] MySQL 建表 + 基础索引
- [ ] Redis 接入，热点数据缓存
- [ ] 对象存储 + CDN 接入，完成视频播放闭环
- [ ] 部署到 K8s，打通 CI/CD

### 阶段二：服务拆分（引入微服务）

- [ ] 按「用户 / 内容 / 播放 / 搜索 / 弹幕 / 推荐」拆分服务
- [ ] 引入 API 网关（鉴权、路由、限流）
- [ ] 内部服务间使用 gRPC
- [ ] 引入 Kafka，异步化弹幕、播放埋点、转码任务
- [ ] 搜索接入 Elasticsearch
- [ ] 多级缓存落地（网关 / Redis / 本地缓存）

### 阶段三：高可用（稳定性保障）

- [ ] 多副本 + 跨可用区部署
- [ ] 限流、熔断、降级、超时与重试、幂等
- [ ] 数据库主从 + 自动故障切换
- [ ] 全链路可观测（Prometheus + Grafana + Jaeger + Loki）
- [ ] 告警规则与值班流程
- [ ] 蓝绿 / 金丝雀发布

### 阶段四：规模化（性能与成本优化）

- [ ] 分库分表落地，冷热数据分离
- [ ] 视频转码集群，多码率 + HLS 切片
- [ ] CDN 预热与回源率优化
- [ ] 推荐系统上线
- [ ] 压测与容量规划，HPA 自动扩缩容
- [ ] 异地容灾演练

---

## 5. 里程碑与时间建议

| 阶段 | 预估周期 | 验收标准 |
| --- | --- | --- |
| 阶段一 | 2~4 周 | 核心链路可跑通，视频可播放 |
| 阶段二 | 4~6 周 | 服务可独立部署，网关统一接入 |
| 阶段三 | 3~4 周 | 压测达 P99 目标，故障自动切换 |
| 阶段四 | 持续迭代 | 满足峰值 QPS 与回源率目标 |

---

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 拆分过早起引入复杂度 | 先单体跑通，再按流量瓶颈拆分 |
| 热点番剧瞬时流量 | CDN 预热 + 多级缓存 + 限流降级 |
| 数据一致性问题 | 幂等设计 + 事务消息 + 最终一致 |
| 视频带宽成本 | CDN 分层缓存 + 回源率监控 + 转码压缩 |

---

## 7. 验收清单（DoD）

- [ ] 核心接口压测 P99 < 100ms
- [ ] 可用性 99.95% 以上
- [ ] 回源率 < 5%
- [ ] 全链路有监控与告警
- [ ] 关键接口具备限流 / 熔断 / 降级能力
